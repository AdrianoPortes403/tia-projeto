Análise de complexidade de tempo e espaço (notação Big-O)

O que é complexidade. A complexidade de um algoritmo mede como o seu custo
cresce quando o tamanho da entrada, chamado n, cresce. A complexidade de
tempo conta quantas operações básicas são executadas; a complexidade de
espaço conta quanta memória extra é usada. Não medimos segundos, porque eles
dependem da máquina: medimos a taxa de crescimento. A notação Big-O, como
O(n), dá um limite superior para esse crescimento. A notação Theta, como
Θ(n), dá o limite justo (cresce exatamente nessa ordem) e Ômega, Ω(n), o
limite inferior.

Regra das constantes e do termo dominante. Na notação assintótica,
constantes e termos de menor ordem são descartados, porque para n grande
só o termo que cresce mais rápido importa. Exemplo: f(n) = 3n² + 100n + 5000
é Θ(n²), pois n² domina 100n e 5000. Do mesmo modo, um algoritmo que executa
sempre exatamente 5 operações, qualquer que seja n, tem complexidade O(1)
(tempo constante): um número fixo de operações não cresce com n.

Ordem de crescimento das funções mais comuns, da mais lenta para a mais
rápida: O(1) constante, O(log n) logarítmica, O(n) linear, O(n log n),
O(n²) quadrática (n ao quadrado), O(n³) cúbica e O(2ⁿ) exponencial.
Funções exponenciais superam qualquer polinômio para n suficientemente
grande. Por isso, para entradas muito grandes, um algoritmo O(n log n)
vence um O(n²) mesmo que tenha constantes maiores: n log n cresce mais
devagar que n².

Laços simples e laços aninhados. Um laço for i in range(n) cujo corpo tem
custo constante executa o corpo n vezes: n · O(1) = O(n), complexidade
linear. Dois laços aninhados, cada um de 0 a n−1, executam o corpo interno
n vezes para cada uma das n voltas do externo: n · n = n², complexidade
quadrática. Somar todos os elementos de uma matriz n × n também é O(n²),
porque a matriz tem n · n = n² elementos e cada um é visitado uma vez.

Laço triangular. Quando o laço interno começa no índice do externo, como em
for i in range(n): for j in range(i, n), o total de execuções do corpo é
n + (n−1) + … + 1 = n(n+1)/2. Pela regra do termo dominante, isso é
Θ(n²): metade de n² continua sendo quadrático.

Sequência soma, aninhamento multiplica. Etapas executadas uma DEPOIS da
outra se somam: um laço O(n) seguido de dois laços aninhados O(n²) dá
O(n) + O(n²) = O(n²), pois prevalece o termo dominante. Só etapas aninhadas,
uma DENTRO da outra, se multiplicam.

Melhor caso, pior caso e caso médio. O custo de um algoritmo pode depender
dos dados, não só de n. A busca linear, por exemplo, termina na primeira
comparação se o valor está na primeira posição (melhor caso, O(1)), mas
compara todos os n elementos se ele está no fim ou não existe (pior caso,
O(n)). Em média, com o valor em posição aleatória, compara cerca de metade,
o que ainda é O(n). Quando não se diz qual caso, a análise costuma ser a do
pior caso, porque é a garantia que vale para qualquer entrada.

Acesso e busca em vetor. Acessar v[i] em um vetor (array) pelo índice custa
O(1): o endereço é calculado diretamente (base + i · tamanho do elemento),
sem percorrer o vetor. Já a busca linear por um valor em um vetor NÃO
ordenado custa O(n) no pior caso, quando o valor não está no vetor ou está
na última posição e todos os n elementos são comparados.

Complexidade logarítmica (tempo logarítmico). A busca binária em um vetor ordenado é O(log n):
a cada passo o intervalo de busca cai pela metade e, após log₂ n passos,
resta um elemento. O mesmo vale para um laço que divide a variável por 2 a
cada volta, como i = n; while i > 1: i = i // 2, que executa cerca de log₂ n
vezes. Um laço que dobra j (j = j * 2) até chegar a n também dá log₂ n
voltas; repetido dentro de um laço de n voltas, o total é n · log n.

Recorrências e Teorema Mestre. Algoritmos recursivos são descritos por
recorrências da forma T(n) = a T(n/b) + f(n). Compare f(n) com n^(log_b a).
Caso 1: se n^(log_b a) cresce mais que f(n), T(n) = Θ(n^(log_b a)); exemplo:
T(n) = 2T(n/2) + Θ(1) dá Θ(n), como percorrer uma árvore binária completa.
Caso 2: se f(n) = Θ(n^(log_b a)), T(n) = Θ(n^(log_b a) · log n); exemplos:
o merge sort, T(n) = 2T(n/2) + Θ(n), é Θ(n log n), e a busca binária
recursiva, T(n) = T(n/2) + Θ(1), com n⁰ = 1, é Θ(log n). Caso 3: se f(n)
cresce mais, T(n) = Θ(f(n)).

Recursão exponencial. O Fibonacci recursivo ingênuo, fib(n) = fib(n−1) +
fib(n−2), faz cada chamada gerar duas outras. O número de chamadas cresce
exponencialmente, Θ(φⁿ) com φ ≈ 1,618, e é limitado superiormente por
O(2ⁿ). Guardar os resultados já calculados (memoização) reduz o tempo para
O(n).

Custo amortizado. Um vetor dinâmico (como a lista do Python) dobra a
capacidade quando fica cheio. Uma inserção no final (append) às vezes custa
caro, porque copia tudo, mas as cópias somam 1 + 2 + 4 + … < 2n para n
inserções. Dividindo por n, o custo médio, chamado custo amortizado, é O(1)
por inserção.

Complexidade de espaço. Conta a memória ADICIONAL, além da entrada.
Inverter um vetor no próprio lugar (in-place), trocando os extremos com dois
índices, usa espaço O(1): só se guardam os dois índices e uma variável
temporária, independentemente de n. A recursão também gasta memória: uma
função fatorial(n) que chama fatorial(n−1), sem memoização, empilha n
chamadas antes de retornar, cada uma com espaço constante, logo usa espaço
O(n) na pilha de chamadas.

Exemplos de referência de algoritmos conhecidos. Acesso a v[i]: O(1).
Busca linear: O(n). Busca binária em vetor ordenado: O(log n). Ordenação
por seleção, por inserção e bubble sort: O(n²) no pior caso. Merge sort:
Θ(n log n) em todos os casos, com espaço adicional O(n). Quicksort: O(n log n)
em média, O(n²) no pior caso. Fibonacci recursivo ingênuo: O(2ⁿ); com
memoização, O(n). Servem de régua para comparar soluções: nenhuma ordenação
baseada em comparações é mais rápida que n log n no pior caso.

Roteiro para analisar um trecho de código. 1) Identifique o que é n, o
tamanho da entrada. 2) Operações simples (atribuição, comparação, acesso a
v[i]) custam O(1). 3) Para cada laço, conte quantas voltas ele dá em função
de n: até n é linear; dividindo ou dobrando a variável é log n. 4) Laços
aninhados multiplicam; etapas em sequência somam. 5) Para recursão, escreva
a recorrência e aplique o Teorema Mestre. 6) No fim, descarte constantes e
termos de menor ordem e fique com o termo dominante. 7) Para o espaço,
conte as estruturas criadas e a profundidade máxima da pilha de chamadas.
